**知行旅行助手｜Agent应用开发**

**项目背景：** 面向多城自由行场景，针对攻略、交通与住宿信息分散，需求变更后日期衔接与预算难以统一的问题，开发支持多轮需求确认、跨会话偏好记忆及逐日行程生成的旅行规划 Agent；通过真实数据查询、状态约束与代码计算，提高规划结果的可执行性和可追溯性。

**技术栈：** Python + FastAPI + LangChain/LangGraph + Qwen + MCP + PostgreSQL + Redis + Chroma + DeepEval + Docker

- **多轮编排与偏好记忆：** 基于单 Agent + StepConfig 动态注入提示词与工具，贯通需求、目的地、交通、住宿、餐饮、行程及预算七步流程；通过 PostgreSQL Checkpointer 恢复会话状态，Store 按用户保存画像与出行历史，支持偏好追加/覆盖、需求回退及后续结果级联失效。
- **真实数据接入与并行查询：** 接入12306、航班时刻、酒店、地图、天气与搜索等9类 MCP 服务，构建高铁、航班、自驾和住宿四类多段查询卡片；以异步并行查询和单段失败隔离降低等待时间，同三段高铁各测3轮，耗时中位数由 **3.84秒降至1.49秒，减少61.3%**；工具守卫将单次587班、7.24万字符的返回裁剪为12班、565字符，约束模型上下文规模。
- **RAG知识库与检索优化：** 基于71份公开攻略、39城内容构建654父块/3120子块知识库，组合父子分块、jieba BM25 + 向量检索、加权RRF、MultiQuery及LLM重排；在18条冻结实体检索题上，**Recall@3由87.96%提升至95.37%，MRR@3由0.676提升至0.787**；引入Redis版本缓存，同查询冷/热各3轮耗时中位数为11.84秒/5.57毫秒。
- **行程生成与事实约束：** 将模型职责限定为需求理解与内容组织，交通段日期、住宿晚数和预算由代码统一计算；仅允许确认真实候选，结合结构校验与规范化处理缺日、空时段和返程遗漏，提供自动确认快速通道及失败后标准流程回退，并通过SSE推送进度、交互卡片和行程结果。
- **后端一致性与质量保障：** 实现JWT鉴权、资源所有权校验、持久卡片、需求版本校验、幂等回执及历史行程版本，防止旧卡片和重复提交污染状态；构建 **120项回归测试、27项专项API检查**，完成断连恢复、跨用户隔离和重启持久化验收，并接入GEval在线异步质检与离线正反样本评测。
