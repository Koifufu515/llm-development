# 文枢本地部署

项目位置：`/Users/jarvis/Desktop/大模型开发/wenshu-project`

## 启动与停止

- 双击 `启动文枢.command`：依次启动数据库、pi、后端、Worker、前端并打开浏览器。
- 双击 `停止文枢.command`：停止本项目的六个服务，保留数据库数据。
- 双击 `查看状态.command`：查看进程状态。
- 电脑重启后需要重新双击启动；没有配置系统开机自启。

终端也可以执行：

```bash
cd '/Users/jarvis/Desktop/大模型开发/wenshu-project'
backend/.venv/bin/python scripts/local_manage.py start
backend/.venv/bin/python scripts/local_manage.py status
backend/.venv/bin/python scripts/local_manage.py stop
```

## 当前模型能力

当前没有配置真实模型 API Key：

- Embedding 使用项目自带的 hash 离线向量；它不具备真实语义能力。
- 检索使用 BM25 + hash 向量融合，重排使用本地启发式降级。
- 回答使用项目原有的原文条款拼接/规则降级。
- pi 服务可启动，但主问答链路暂未启用 pi 模型推理。
- 可以体验登录、文档管理、引用、历史、反馈和异步作业；不能把该模式的结果当成真实 LLM/RAG 的评测效果。

接入真实模型时，编辑根目录 `.env`，填写自己账户的 `DEEPSEEK_API_KEY`，并核对实际可用的
`DEEPSEEK_MODEL`；需要 pi 时再设置 `PI_AGENT_ENABLED=true`。本项目没有使用其他应用中保存的密钥。

需要真实 Embedding / Reranker 时，填写对应服务配置并修改 `EMBEDDING_PROVIDER` 等参数。
切换 Embedding 后必须重新索引所有文档，不能混用原先 hash 向量与新向量；向量维度应与实际返回值一致。
只启用对话模型时可以暂时保留 hash 检索，但答案质量不代表完整语义检索效果。

## 样例与验证

首次启动会导入 `department_files/` 中的 7 份样例文档，并初始化部门、规则、Skill。
这些样例可能含历史时间点，仅用于演示。可提问：

- “校园24小时应急电话是多少？”
- “双学位硕士研究生的开题报告字数要求是多少？”

离线测试：

```bash
cd backend
STORAGE_MODE=memory VECTOR_BACKEND=memory EMBEDDING_PROVIDER=hash EMBEDDING_DIM=128 PI_AGENT_ENABLED=false RERANKER_ENABLED=false DEEPSEEK_API_KEY='' RELAY_API_KEY='' .venv/bin/python -m pytest -q
```

依赖版本记录在 `backend/requirements.local.lock.txt`。前端和 pi 使用原项目 npm 锁文件。
若修改前端源码，应执行 `npm run build` 并重新复制 `.next/static` 到 `.next/standalone/.next/static` 后重启。
