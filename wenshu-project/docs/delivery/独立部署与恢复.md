# 文枢独立部署与恢复

正式开发目录在桌面大模型开发/wenshu-project；本机入口 http://127.0.0.1:3000 ，API 8000，pi 8100。双击启动文枢.command，查看状态.command 可查询进程。原Mongo27027/Redis6387不可随意删除。专用 Docker/Kubernetes context为colima-wenshu，不能使用其他项目context。

## 新机器Compose

安装Docker Compose和Python3.11；执行 `python scripts/prepare_compose.py` 生成随机私有配置。编辑 `.local/config/compose.env` 的百炼Key。先建立脱敏映射并确认文本授权，再将 MODEL_EGRESS_ALLOWED=true。默认关闭演示账号；按backend/app/auth.py的账号种子格式在私有位置创建管理员，生产使用自己的账号管理。

依次执行：

```sh
docker compose -f deploy/docker-compose.milvus.yml up -d
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml up -d --build
```

入口13000/API18000；数据库27028仅绑定回环地址。私有.env必须600权限。集群部署使用 deploy/helm/wenshu 和 deploy/k8s/ha-storage.yaml；真实Secret应单独注入，不能提交到Git。监控位于deploy/monitoring，单节点三副本实验仅证明组件故障切换，不是节点容灾。

## 空库恢复

快照 `data/sample/facts.redacted.json` 只包含七份样例的脱敏业务事实；不含用户账号、会话、密钥、向量或真实学校全量资料。配置新库环境后在backend执行：

```sh
python -m scripts.snapshot_data restore ../data/sample/facts.redacted.json
```

脚本拒绝覆盖非空业务库。备份使用 `python -m scripts.snapshot_data export /安全目录/facts.json --redact`。还原后使用同一Embedding模型text-embedding-v4及1024维，对active文档逐一调用Indexer.reindex，重建独立Milvus collection；切换模型必须新建collection。重建前不可宣称向量恢复完成。

只停止应用可用local_manage进程表；不要执行down -v，原件和数据库卷须保留。K8s演示结束可缩容本项目应用释放内存，恢复用Helm，不能删除PVC。16GB宿主机不适合同时跑多项目和20副本；完整容量实验失败结果保存在reports/hpa-*.json。

### Compose容器内操作

上面的Python命令在已安装backend/requirements.txt并配置目标库的主机环境执行。若完全使用容器，使用同一Compose配置，先把脱敏快照复制进backend容器：

```sh
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml cp data/sample/facts.redacted.json backend:/tmp/facts.json
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml exec backend python -m scripts.snapshot_data restore /tmp/facts.json
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml exec backend python -m scripts.create_admin
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml exec backend python -m scripts.reindex_active
docker compose --env-file .local/config/compose.env -f deploy/docker-compose.full.yml restart backend worker
```

前两步只涉及本机；reindex_active会向已配置模型发送经授权的脱敏样例条款。授权或密钥未配置时应保持关闭，不能以hash结果冒充语义重建。恢复后重启使BM25重新加载事实块。登录使用自己创建的管理员；不要在正式部署启用默认密码演示账号。
