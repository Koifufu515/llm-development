# 知行 + ShanYangClaw 一周交付与学习计划

**Goal:** 七个学习日内，完成两个真实模型驱动、可本地演示、关键行为可验证的核心版本，并让用户能说明关键链路及设计取舍。

**Architecture:** 知行以单 Agent + 显式状态机控制旅行流程；山羊以 DeepAgents 组织开发任务，在专用一次性 Docker 容器内执行代码。复用本机 uv/Colima 基础设施，各项目独立虚拟环境、数据库命名空间和配置，不共享业务状态。

**Tech Stack:** Python、uv、FastAPI、LangChain/LangGraph、DeepAgents、PostgreSQL、Docker/Colima；山羊后台队列按原代码使用 Redis/arq。具体 SDK 版本和调用签名在实施当天以原代码、官方文档和实际验证为准，不直接采用教程无上限依赖。

## 时间与合作方式

- 已确认用户每天 4～5 小时；项目 3～3.5 小时，相关八股 30～45 分钟，Hot100 30～45 分钟，合计 4～5 小时。七天项目时间约 21～24.5 小时。
- 第一天指下一个完整学习日，不要求在 10 月 24 日晚完成全天安排。
- 助手负责源码整理、实现、依赖排查、验证和文档；用户负责需求选择、关键链路理解、观察验证、提出行为修改、口述复盘，不要求逐行手敲。
- 每天按 20 分钟场景与方案、90～120 分钟分段实现/演示、45～60 分钟关键代码与改动、25～30 分钟验收复盘推进。每块都可以单独继续，不等整天结束才演示。
- 不把运行成功记为用户已掌握；用户能讲清目的/链路/取舍，并能给出一个边界场景，才记录理解通过。

## 两个项目的完成定义

知行：真实模型识别并补齐旅行需求 → 当前步骤只暴露允许工具 → 至少两类旅行工具（其中至少一个真正经 MCP）→ 行程/预算结构化输出 → 追问修改与下游清理 → PostgreSQL 会话恢复 → SSE 和简单页面演示。

山羊：提交受控样例仓库与修复要求 → 规划 → Coder 修改 → Docker 内运行测试 → Reviewer 审查 → 返回补丁与测试证据；同时具备后台任务状态、一个有效的人工审批点及最小执行审计。

两者都需要启动说明、配置模板、依赖锁、关键场景回归结果、已知限制及一次用户提出的行为修改。山羊沙箱仅面向本地受控样例，不宣称具备生产多租户安全能力。
