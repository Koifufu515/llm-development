# 从一次真实请求复盘Quarry

先打开开发调试台`http://127.0.0.1:8110/web/debug.html`，输入“南普陀寺开放时间”。平台返回证据，知行等上游负责回答。

沿一条完整正常链路看：`sdk/quarry_client.py`发HTTP请求 → `api/security.py`从Key读取服务端标签、集合与Redis额度 → `api/routes.py`校验请求并设置总超时 → `pipeline.py`查active集合 → `retrieval/pg/searcher.py`并发向量化和线程池分词 → 一条SQL双路召回与RRF融合 → 托管重排或故障降级 → 同节去重 → 回捞父块和邻块 → 按字符区间遮蔽事实 → 三档上下文预算 → 引用与最高dense分拒答建议 → HTTP JSON → SDK解析并拼提示词 → BackgroundTasks记查询日志。

正常链路理解后再穿插四组实际故障：public访问corp-policy（403或无证据）、强过滤默认扫描漏召回（5000条合成实验）、worker领取后被kill（PEL接管和三次死信）、同价景点的quote错属（红测试及修复）。脚本与结果在scripts/、tests/、reports/，无需逐行手敲。

复盘时必须能解释：simple tsvector不是BM25；RRF融合分不是概率；拒答阈值看dense而非重排分；引用text不遮蔽而context遮蔽；unverified不代表真实官方价格；模型裁判支撑率不等于事实准确率；缓存向量压测不等于线上端到端QPS。

助手运行通过不能替代用户亲自触发、修改行为和口述复盘。本次先交付完整实现，再按正常业务链连续讲解，不按题号频繁打断。
