# 后端八股逐题讲解与口述整理 Skill

## 目标与定位

用户在学习后端开发八股，基础不必预设为已掌握计算机网络、操作系统、数据库和 Java/Python 后端原理。目标是每题达到：理解机制 → 能推演具体例子 → 识别关键追问 → 能直接按分点回答。教学深度保持面试标准，不因用户初学而回避术语；术语必须解释。

本 Skill 管理“后端八股”的教学与口述版格式。用户另行讨论自己的 Agent 项目、LeetCode、研究课题时，不要擅自套用八股题目顺序。

## 权威资料与题目连续性

1. 题目顺序和原始要点以使用者实际提供的题库为依据（可为《代码随想录知识星球-八股文速记版.pdf》或其他明确指定的材料）。先按文件名检索当前资料，不使用旧的固定目录，不猜下一题或换成常见题单。
2. 学习进度从当前会话和最新笔记核对；整理成果保存到使用者指定或已确认的目录，使用稳定文件名和同名PDF。成品题数不等于用户已掌握的题数，不把过去日期或题号写成永久进度。
3. 原书确有错误或过时说法时，明确区分原文、修正和补充，口述采用准确答案；必要时核验权威技术来源。若用户明确要讲独立技术问题，直接回答，不强行套原书题序。
4. 原题无法检索时说明无法核实，不编造原文；用户已给出题目或正文时使用已有材料继续。

## 每道题的固定教学流程

### A. 题意与关键原理

开头写 `## 第 N 题：<原文题目>`。从问题考察点切入，直接讲核心概念与为什么出现这种机制。允许 1–3 个小标题，不按每句话单独成段。已学过的知识简要衔接，避免整篇回顾上一题。

关键机制必须立即跟一个具体情境/反例/执行过程。例如讲 TCP 队头阻塞，要展示一条连接中某个包丢失影响后续交付的事实链，而不是只说“可靠性导致阻塞”。新术语首次出现时解释其含义、职责和与类似术语的区别。涉及多个参与方的交互、数据流或状态转换时，优先用简洁、准确的彩色示意图辅助理解；不要用 emoji 拼接成所谓的彩色流程图，也不必为每个概念都画图。图解用于学习，最终口述答案仍保持简短。

### B. 面试考点与追问

讲清主考点及易混淆结论。只选与原题紧密相关的 1–2 个高价值追问，解释原理和边界，不机械扩展。与用户学过的 FastAPI/LangChain 等有自然联系时可加一句应用场景，不强行牵扯项目。

### C. 默认面试口述格式（用户本次指定格式优先）

以 `### 面试回答` 为小标题（可用 `**面试回答：**`），对于适合分点的知识型题目，使用**Markdown 有序列表**，每点用完整句子解释机制：

`1. **加粗关键词。** 后面紧跟一到三句完整、自然、可直接在面试现场复述的技术描述。`

`2. **加粗关键词。** 完整说明具体机制、原因或区别。`

`3. **加粗关键词。** 完整说明，并保持与原书要点一一对应。`

要求：
- **每一点必须有序号 `1.`、`2.`、`3.`；不可使用 `01 02 03`。** 对正在教学的新答案，可以在确有利于复述时加粗原有核心术语；对用户已提交的口述稿做 PDF 排版时，尊重原文，不硬加“关键词。+回答”的概括词。
- 不写整段没有编号的“我理解主要有四点：第一……第二……”；不写大块 `>` 引用；不使用 WritingBlock、卡片、流程框、彩色容器、花哨表格。
- 不是 PPT 提纲：每个编号后是**自然完整、口语流畅的句子**，不能只罗列关键词；同时避免冗长到不便背诵。
- **讲解可以详细，口述必须极简。** 原理、反例、图示、追问可以在教学正文详细解释；最终背诵版仅保留直接回答题目的高频要点。条数由问题复杂度和回答完整性决定：两三点足够就只写两三点，确实需要更多点才能解释清楚时就增加，绝不为了详细而凑条数或为减少条数遗漏必要内容。
- **严格贴合原题问法。** 先判断题目真正问的是什么，避免把相邻知识点、不同版本协议、延伸的应用案例和低频细节塞进背诵版。它们可放在讲解或追问，不应稀释主答案。
- 保留原书与题目直接相关的核心要点，遵循原文因果顺序；原文答案与题目有偏差时先解释偏差，口述用最常见、最准确的直答。没有依据的补充不得进入口述答案；对错误说法要修正。
- 代码名、协议字段、重要术语可用行内代码突出。少量标题即可，整篇不堆分隔线、重复总结、学习任务和“下一题预告”。

## 用户确认的精简口述示例（第 13 题）

### 面试回答

1. **建立多个连接。** 客户端可以和同一个服务器建立多条 TCP 连接，通过源 IP、源端口、目标 IP 和目标端口组成的四元组进行区分，从而并发处理多个 HTTP 请求。
2. **Keep-Alive 连接复用。** HTTP 可以通过 Keep-Alive 机制保持已建立的 TCP 连接，允许后续 HTTP 请求继续使用，减少反复建立和关闭连接的开销。
3. **性能优势。** 多连接有助于提高 HTTP/1.1 的请求并发能力，复用已有 TCP 或 HTTPS 连接还可以减少重复握手带来的开销。

口述答题要按原问题确定 2–3 个最核心且互不重复的要点；这一示例用于强调简洁和贴题，不代表每题必须有 3 点。

## 最终自检

交付前逐项核查：① 题号、题目与原书完全一致；② 原文每个核心要点已保留；③ 机制有可理解的实例；④ 事实修订与原文清楚区分；⑤ 口述答案条数取决于题目真正需要的内容，每点是“序号 + **关键词。** + 完整句子”，不加入低频延伸；⑥ 无 WritingBlock、卡片、没必要的花哨容器；图解仅用于教学；⑦ 不擅自改题序或追加未经要求的新题。

## 与其他 Skill 的边界

仅用于独立知识型八股及技术原理教学；项目经历类问答使用“项目面经”，算法刷题使用“算法题讲解”。整理成 PDF 时调用“文档整理与制作”；不要在末尾添加独立的速查、总结或背诵页。



## 模板与规则边界

普通语言遵循“回复格式”。本skill保留原理教学、题序核对和口述格式，不再维护字体、颜色、目录和PDF模板。用户要求导出笔记时调用“文档整理与制作”的讲义模板；只要求聊天讲解时不创建文件。原书、笔记和学习进度是任务资料，不是skill自身的固定状态。

## 分享版的资料依赖

本安装包不包含原始题库和任何使用者的学习进度。使用前读取当前使用者提供的题库；没有题库时可讲其明确提出的技术问题，不声称已知题序或已读原书。

## 配套规则可用性

本套共5个Skill，建议一并安装。引用其他配套Skill时按其规范名定位；若尚未安装，不声称已调用，不因此阻塞当前可独立完成的内容，必要时说明缺少的模板或能力。
