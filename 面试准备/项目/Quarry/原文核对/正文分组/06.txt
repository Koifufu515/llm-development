数据模型层的约束成本几乎为零，却能挡住几乎所有"形状"层面的错误。

2.6.4 部分索引：只给一部分行建索引
部分索引就是带
WHERE
的索引：只给满足条件的行建。本项目四个部分索引，逐个说清楚它们在干什么。
① 向量索引只建在子块上（
WHERE level = 1
）
父块本来就没有向量（
embedding
是 NULL），NULL 本来就不会进 HNSW 索引。所以这个 WHERE 不是为了省内存，而是为了把"只检索子块"这条规则写死在索引上：将来就算有人给父块也算了向量，它们也进不了检索，不会出现"父块和它自己的子块同时被命中、内容重复"的情况。
它带来一个必须知道的后果：
查询里必须写
level = 1
，数据库才会用这个索引
。部分索引只"覆盖"满足条件的行；你的查询如果没有声明"我只要
level = 1
的行"，数据库无法确定索引里有你要的全部数据，只能放弃它。
动手验证
。在 psql 里：
EXPLAIN
的意思是"别真的执行，告诉我你打算怎么执行"。这里用
(SELECT embedding ... LIMIT 1)
随便拿一个已有的向量当查询向量，省得手敲 1024 个数字。
A 的输出里能看到

：索引用上了。
B 的输出里找不到
chunks_embed_hnsw
，取而代之的是一个
Sort
（把所有行取出来、全部算一遍距离再排序），下面可能是

，也可能是用别的索引把整张表扫一遍。
小数据量下两者都很快，看不出差别；到了几十万块，B 的写法会慢几个数量级。
第四章所有检索 SQL 都带着

，原因就在这里
。看完之后敲

恢复默认。
② 全文索引只建在子块上（
WHERE level = 1
）
同样的道理：检索粒度是子块，父块不参与全文检索。查询里同样要带
level = 1
。
③ 父指针索引只建在子块上（
WHERE level = 1
）

服务的是"给定一个父块，找它的所有子块"，比如父块内容更新时要清理它名下的旧子块。父块的

④ 邻块索引只建在父块上（

）
邻块补全的意思是"命中一个父块后，把它前后各一个父块也带上，让上下文更完整"。只有父块需要这个操作，子块用不着。

，前提是第三章写入父块时，

2.6.5 索引不是越多越好
每插入一个块，八个索引都要跟着更新。批量导入十万块时，维护索引的开销可能比插入数据本身还大。
第三章会讲一个技巧：
大批量导入前先临时删掉索引，导入完再一次性重建
。这样索引只按最终数据建一遍，不用一条条维护。代价是重建期间检索不可用，所以只在初次导入或全量重灌时用。
动手看看每个索引多大（可选

第一章只灌了几个块，每个索引都只有几十 KB。第三章灌入完整语料后再看一次，HNSW 会明显最大：它要维护整张"交通网"。
2.7 稳定块标识
这一节是本章的核心，也是本章唯一大段动手的一节。
先用一句话说清
chunk_id
是什么：
它是用卡片内容算出来的"指纹"，不是随机发的号码
。
打个比方：去银行排队取号，每次拿到的号都不一样；按指纹，同一个手指按一百次都一样。
chunk_id
要的是后一种：同样的内容、在同样的位置，不管什么时候、在哪台机器上算，都得到同一个 ID。
这一个决定，同时撑起三件事：
撑起什么
怎么撑
增量索引
重新接入一份文档时，ID 已经在库里的块说明内容没变，不用重算向量；改一个字只重算那一个子块
队列幂等
同一条消息被处理两次，写入的是同样的 ID，ON CONFLICT 让第二次变成"更新"而不是"再插一条"
跨机器对账
两台机器各自导出快照，同样的内容 ID 相同，校验和能直接比
一个决策，三处受益。反过来，这个决策错了，三处一起塌。

为什么要放进一个事务

顺序为什么是"先退役、再上岗"

"新建 → 重灌 → 评测 → 原子切换 → 留回滚窗口"这套流程在本课程会反复出现：这里的换向量模型、第三章的切分策略调整，都是它。流程本身比哪一次的具体实现都更通用。

2.8 迁移管理
第一章 3.5 节讲了 Alembic 的基本用法。这一节往深走一层：迁移多起来之后怎么管，然后动手写本项目的第二个迁移。
先复习一句：迁移就是"对数据库结构的一次改动"，写成一个文件、按顺序编号。Alembic 在数据库里有一张
alembic_version
表，记着"当前走到了哪一步"，执行
alembic upgrade head
时只跑还没跑过的那些。你可以把它想成数据库结构的"存档点"。
2.8.1 迁移的命名规范
规范一：用
--rev-id
自己指定一个带序号的版本号
。
第一章你已经这么做了：
不加
--rev-id

a1b2c3d4e5f6
）当版本号，文件名也是
a1b2c3d4e5f6_core_tables.py
。迁移一多，随机 ID 很难按顺序找。本项目的六个迁移统一编号

，按文件名一排序就是执行顺序。
