**哈啰智能客服｜托管 Agent 与会话编排平台**

**项目背景：** 面向顺风车、小哈换电等客服场景，在用户申请转人工后由托管 Agent 先行承接咨询与业务办理，人工按需介入。针对复杂流程推进不稳定、订单切换后上下文混用、热线等待时间长等问题，完善会话编排、工具执行与流式响应链路。

- **会话编排与状态管理：** 针对复杂订单办理中模型跳过前置步骤、工具失败后误推进流程的问题，引入**意图识别 Agent＋确定性状态机**，按“取证—判责—协商—处置”装配阶段说明与工具；结合**执行计划与状态提交分离、版本校验及订单作用域隔离**，处理多轮推进、失败重试和中途切单，支撑顺风车、小哈换电日均约 **1.97 万、2,700 条**托管会话。
- **工具扩展与人工协同：** 通过**工具预调用**提前获取业务数据，按协议将调用结果注入首轮上下文；将专项子 Agent 封装为工具，支持主 Agent 委派执行，并通过 **Hook＋HITL 人工审批**拦截敏感操作、审批后恢复会话。平台上线后，单坐席并发接待能力由 **1v5 提升至 1v20**，两条业务线进入托管后未由人工接管的比例分别达到 **96.6%、88.7%**。
- **热线并发编排与打断处理：** 针对多次模型调用串行累积等待的问题，并发准备**业务路由、非业务意图识别、打断检查与承接话术**，按“打断优先—特殊意图接管—正常业务放行”统一仲裁；通过**承接先行、主回复按序输出及关键节点打断复查**，处理用户挂断、转人工和旧轮次迟到结果，避免无效回复继续输出。
- **执行资源隔离与链路观测：** 针对慢工具 RPC 占用共享执行资源、拖慢模型流式读取的问题，拆分模型、工具及打断检查的执行资源，采用 **Java 21 虚拟线程＋信号量限流＋排队超时**控制任务堆积；基于 Hook 采集模型调用、Token 消耗、工具执行与异常事件，通过 **Reactor Sink**提供可订阅事件流，支持调试追踪与按渠道裁剪输出。
- **外投风险识别与业务接管：** 结合进线次数、历史外投、同单工单等**静态特征＋LLM 会话语义分析**识别投诉升级倾向，命中后切换专属 Agent 并关联工单跟进，完善高风险诉求的处理路径。托管平台整体上线后，顺风车、换电全托管不满意率分别由 **32.6% 降至 25.9%**、**35.6% 降至 27.8%**。
